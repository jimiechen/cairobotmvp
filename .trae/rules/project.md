# Trae 项目执行规则

## 1. 文件定位

本文件用于约束 Trae 在本仓库中的任务执行方式。

Trae 的职责是按照 Issue、PRD、ADR 和 TDD 流程协助开发，不是自行决定产品方向。

## 2. 执行任务前必须阅读

每次执行任务前，必须先阅读：

1. `AGENTS.md`
2. 当前任务相关的 PRD
3. 当前任务相关的 ADR
4. 当前 Issue 或用户任务描述
5. 当前模块目录下的 README，如果存在

如果缺少 PRD、ADR 或 Issue，应先提示补充，而不是直接写代码。

## 3. 默认工作方式

Trae 应按以下方式工作：

1. 复述任务目标。
2. 判断任务涉及哪些文件。
3. 判断是否需要测试。
4. 如果是开发任务，先写测试。
5. 等测试失败后，再写最小实现。
6. 运行测试。
7. 输出变更文件清单。
8. 输出测试结果。
9. 提醒是否需要提交 PR。

## 4. 禁止行为

不得：

- 不读需求直接写代码。
- 一次性生成完整系统。
- 修改与任务无关的文件。
- 擅自新增技术栈。
- 擅自修改目录结构。
- 擅自修改 PRD 范围。
- 擅自删除测试。
- 擅自删除文档。
- 用“以后再补”跳过 P0 验收要求。

## 5. 输出要求

任务完成后必须输出：

- 本次完成了什么。
- 修改了哪些文件。
- 新增了哪些测试。
- 运行了哪些命令。
- 测试是否通过。
- 是否有风险或待确认事项。

## 6. 任务汇报要求

Trae 每次任务完成后，必须输出任务完成汇报。

任务完成汇报必须包含：

- 完成内容。
- 修改文件。
- 新增测试。
- 运行测试命令。
- 测试结果。
- Bug 与事故。
- 文档同步情况。
- 风险与遗留问题。
- 需要项目主控确认的问题。

每日 22:00 前必须提交日报。

如果当天没有代码变更，也必须提交无代码变更日报。

如果发生事故，必须立即停止当前任务并提交事故报告，不得等到日报。
