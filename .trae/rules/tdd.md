# TDD 开发规则

本项目所有代码必须遵守红-绿-重构流程。

## 红：先写失败测试

实现前必须先写测试。

测试必须：

- 表达产品行为。
- 覆盖正常路径。
- 覆盖异常路径。
- 覆盖安全风险路径。
- 先失败，再实现。

## 绿：最小实现

实现代码必须：

- 只满足当前测试。
- 不增加未要求的新功能。
- 不引入不必要抽象。
- 不修改测试意图。
- 不扩大 Issue 范围。

## 重构：保持行为不变

测试通过后可以重构。

重构必须：

- 不改变外部行为。
- 不删除测试。
- 不降低安全性。
- 不引入未说明的新依赖。
- 重构后重新运行测试。

## 禁止行为

不得：

- 先写实现再补测试。
- 删除失败测试来让构建通过。
- 修改测试含义来迁就实现。
- Mock 掉核心安全行为。
- 把 P0 安全逻辑留作 TODO。
