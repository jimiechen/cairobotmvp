# CaiRobot MVP 每日汇报 Skill

## 1. Skill 职责

本 Skill 强制执行 CaiRobot MVP 项目的任务汇报机制。

**负责**：
- 每日日报提交
- Bug 跟踪记录
- 事故上报
- 风险上报
- 阻塞上报

详细规则参见：[.trae/rules/reporting.md](../../.trae/rules/reporting.md)

## 2. 强制执行步骤

### 2.1 日报流程

每天必须完成以下工作：

1. **21:30** - 停止扩大开发范围
2. **21:30-21:45** - 整理今日修改文件
3. **21:45-22:00** - 生成日报
4. **22:00 前** - 提交日报
5. **22:00 后** - 将日报蒸馏为 Markdown
6. **同步更新** - LLM Wiki

### 2.2 日报内容

每份日报必须包含：

| 内容 | 说明 |
|---|---|
| 日期 | 当前日期 |
| 当前分支 | 正在开发的分支 |
| 当前 Issue | 关联的 Issue |
| 今日完成内容 | 详细描述 |
| 修改文件清单 | 路径、类型、说明 |
| 新增测试清单 | 文件、内容、状态 |
| 测试命令与结果 | 实际命令和输出 |
| Bug 列表 | 等级、状态、说明 |
| 事故说明 | 是否有事故 |
| 风险事项 | 风险描述 |
| 阻塞事项 | 阻塞原因 |
| 明日计划 | 计划任务 |
| 需要确认的问题 | 待主控决策 |

### 2.3 Bug 上报

发现 Bug 时必须记录：

| 字段 | 说明 |
|---|---|
| Bug ID | 唯一标识 |
| 严重等级 | P0/P1/P2/P3 |
| 当前状态 | 新增/处理中/已修复/待确认 |
| 相关 Issue/PR | 关联关系 |
| 复现步骤 | 详细步骤 |
| 期望行为 | 预期结果 |
| 实际行为 | 实际结果 |

### 2.4 事故上报

发生以下情况必须**立即**上报：

- S0：严重破坏仓库、数据、密钥或核心文档
- S1：破坏核心模块或核心流程
- S2：影响局部模块

不得等到日报时间。

## 3. 完成前硬校验清单

日报提交前，必须确认：

- [ ] 今日完成内容有具体描述
- [ ] 修改文件清单完整
- [ ] 测试命令和结果真实
- [ ] Bug 列表准确
- [ ] 风险/阻塞事项已列出
- [ ] 明日计划明确

## 4. 报告位置

| 报告类型 | 位置 |
|---|---|
| 日报 | `docs/reports/daily/` |
| Markdown 蒸馏 | `docs/reports/distilled/` |
| Standalone HTML | `docs/reports/html/` |

## 5. 联动 Skill

- 任务完成时激活 cairobot-daily-report
- Bug 发现时激活 cairobot-tdd-loop（写 Bug 复现测试）
- 事故发生时激活 cairobot-engineering-workflow（上报）
