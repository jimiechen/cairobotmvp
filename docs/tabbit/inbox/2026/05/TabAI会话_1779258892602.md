### **一、重新定义架构边界**

现在应该把系统分成三层：

```text

  ↓
Gateway 协议适配层
  ↓

  ↓

```

其中：

#### **Gateway 层职责**

Gateway 负责：

```text

2. 解析 MessagePacket。
3. 根据 maxType + minType 路由。
4. 处理 MessagePacket.data 的 JSON 编解码 / 转义。
5. 调用对应 Module。
6. 包装统一响应。
7. 做鉴权、审计、trace、错误映射。
```

Gateway 不应该承载具体业务逻辑。

#### **Invoker 层职责**

Invoker 负责：

```text
1. local 模式：进程内调用 Module。
2. tars 模式：通过 TarsGo 调用远程 Module 服务。
```

Invoker 只是调用方式适配，不改变业务输入输出语义。

Module 负责：

```text
1. 独立业务逻辑。
2. 独立单元测试。
3. 独立集成测试。
4. 独立文档。
5. 接收 Protobuf message 定义的对象，或接收 JSON DTO。
6. 不直接依赖 HTTP Gateway。
7. 不直接依赖 MessagePacket envelope。
```

所以 users、auth、groups、topics 这些模块应该都可以单独测试，而不是必须通过 Gateway 才能测。

### **二、MessagePacket 的定位要重新说清楚**

`MessagePacket` 不是业务对象。

它是网关统一入口的 envelope。

也就是说：

```text
MessagePacket = 路由信封
MessagePacket.data = 业务 payload
业务 payload = JSON 格式，语义来自 Protobuf message 定义
```

更准确地说，`MessagePacket.data` 承载的是：

```text
符合 Protobuf message 语义的 JSON payload
```

例如某个请求协议是：

```protobuf
message CreateUserRequest {
  string username = 1;
  string phone = 2;
}
```

那么 Gateway 收到的逻辑数据应该是：

```json
{
  "maxType": 2200,
  "minType": 2201,
  "data": {
    "username": "alice",
    "phone": "13800000000"
  }
}
```

或者如果当前 `message.proto` 里 `data` 是 bytes，那么内部可以把 `data` 存成 UTF-8 JSON bytes：

```text
MessagePacket.data = []byte(`{"username":"alice","phone":"13800000000"}`)
```

但这里有一个重要陷阱：如果 `MessagePacket.data` 在 Protobuf 里定义为 `bytes`，直接用标准 `protojson` 序列化整个 `MessagePacket` 时，`bytes` 字段会被转成 base64，而不是 JSON object。

所以如果项目要求 HTTP 层 `data` 是 JSON，建议明确两层模型：

```text
HTTP 层：GatewayPacketJSON，data 是 json.RawMessage 或 object。
内部层：MessagePacket，data 是 UTF-8 JSON bytes。
```

这样可以避免：

```text
HTTP data 变成 base64
```

也避免业务层误以为自己要处理 MessagePacket。

### **三、模块接受的是 Protobuf 定义对象或 JSON，不是 MessagePacket**

你说的这个规则应该上升为硬规则：

```text
业务 Module 不接收 MessagePacket。
业务 Module 接收 Protobuf message 定义对象，或接收与该 Protobuf message 对齐的 JSON DTO。
```

例如 users 模块：

```text

```

或者：

```text
users.Handle(ctx, json.RawMessage) -> json.RawMessage
```

但更推荐长期目标是：

```text
Gateway 将 MessagePacket.data JSON 解析为 Protobuf message 对象。
Module 接收强类型 Protobuf message 对象。
Module 返回强类型 Protobuf message 对象。
Gateway 再转成 JSON payload 写回 MessagePacket.data。
```

也就是：

```text
MessagePacket JSON
  ↓
Gateway decode data JSON
  ↓
Protobuf message object
  ↓
Module method
  ↓
Protobuf message response object
  ↓
Gateway encode response JSON
  ↓
MessagePacket JSON response
```

这样业务模块就不会被网关协议污染。
