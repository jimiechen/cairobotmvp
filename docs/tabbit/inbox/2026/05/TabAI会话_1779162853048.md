# 四、TLOG Sink 实现

请实现 TarsGo TLOG 审计输出，不要使用标准 `slog` 作为主实现，不要引入第三方日志库。

建议接口：

```go
type Sink interface {
    Write(ctx context.Context, event AuditEvent) error
}
```

实现：

```go
type TLOGSink struct {
    logger Logger
}
```

由于 TarsGo 的 logger 类型可能是具体类型或接口不稳定，请先定义项目内部最小接口：

```go
type Logger interface {
    Debug(v ...interface{})
    Info(v ...interface{})
    Warn(v ...interface{})
    Error(v ...interface{})
}
```

或根据实际 `tars.GetLogger("TLOG")` 返回类型调整。

构造函数：

```go
func NewTLOGSink() *TLOGSink {
    return &TLOGSink{
        logger: tars.GetLogger("TLOG"),
    }
}
```

可选构造：

```go
func NewDayTLOGSink() *TLOGSink {
    return &TLOGSink{
        logger: tars.GetDayLogger("TLOG", 1),
    }
}
```

远程日志后续支持：

```go
func NewRemoteTLOGSink() *TLOGSink {
    return &TLOGSink{
        logger: tars.GetRemoteLogger("TLOG"),
    }
}
```

但本阶段默认使用：

```go
tars.GetLogger("TLOG")
```

输出格式：

- 建议 JSON line 字符串。
- 使用 `encoding/json` marshal AuditEvent。
- TLOG 输出级别：
  - 成功调用：Info
  - 鉴权失败/参数错误：Warn
  - 内部错误/超时/panic：Error

示例：

```go
func (s *TLOGSink) Write(ctx context.Context, event AuditEvent) error {
    b, err := json.Marshal(event)
    if err != nil {
        return err
    }

    switch {
    case event.ErrorCode >= 10500:
        s.logger.Error("[AUDIT] ", string(b))
    case event.ErrorCode >= 10400:
        s.logger.Warn("[AUDIT] ", string(b))
    default:
        s.logger.Info("[AUDIT] ", string(b))
    }

    return nil
}
```

如果 TarsGo logger 方法签名与上述不一致，请按实际 API 调整，但必须保持 TLOG 输出。

# 八、TarsGo ServerFilter 实现

请基于 TarsGo 原生 ServerFilter 实现服务端审计。

TarsGo 文档中的 ServerFilter 形态类似：

```go
type ServerFilter func(
    ctx context.Context,
    d Dispatch,
    f interface{},
    req *requestf.RequestPacket,
    resp *requestf.ResponsePacket,
    withContext bool,
) error
```

请按当前项目依赖版本的实际签名实现。如果版本 API 有变化，以实际编译通过为准。

实现目标：

```go
func NewAuditServerFilter(sink Sink) tars.ServerFilter
```

行为：

1. 从 `req` 中读取 servant、method、context/status。
2. 从 req buffer 中计算 request size/hash，如果可访问。
3. 调用 dispatch。
4. 从 resp 中读取 return code / response buffer size/hash，如果可访问。
5. 记录 before 和 after 事件。
6. 捕获 error。
7. 不修改 req/resp。
8. 不吞掉 error。
9. 审计写入失败不影响主链路。

注册方式：

优先使用当前 TarsGo 推荐 API：

```go
tars.UseServerFilterMiddleware(...)
```

如果当前版本只能使用旧 API，则使用：

```go
tars.RegisterServerFilter(...)
```

但文档必须说明：旧 Register API 在部分版本中标记 deprecated，项目优先使用 Middleware API。

# 十、Gateway AuditInvoker 与 TarsGo Filter 的关系

请明确实现：

- Gateway `AuditInvoker` 是网关层审计，覆盖 local 和 tars 两种模式。
- TarsGo `ClientFilter` 是 Tars 客户端框架层审计，只在真实 tars 模式下生效。
- TarsGo `ServerFilter` 是 TarsGo 服务端框架层审计，只在 TarsGo server 运行时生效。
- 三者不是互相替代，而是分层审计。
- 当前最小实现必须至少完成 Gateway AuditInvoker + TLOG Sink。
- 如果真实 TarsGo 依赖已接入，则同时完成 ClientFilter / ServerFilter 编译通过。
- 如果真实 TarsGo server 尚未实现，则先完成共享 auditfilter 包和测试，README 标注接入点。
