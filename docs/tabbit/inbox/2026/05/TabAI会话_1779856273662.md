#### **🔴 修改 1：protobuf.js 与 google-protobuf 冲突（主控直接拍板，不让方案作者选）**

```text
裁决：✅ 方案 A — 统一使用 google-protobuf + 预生成 TS 代码
```

**为什么主控直接拍板：**

```text
1. 一个 monorepo 内同时存在两套 protobuf 运行时，必然在未来 6 个月内
   出现"两边对同一 .proto 行为不一致"的诡异 bug，是典型的技术债复利
2. 现有 typescript/web/src/utils/proto-client.ts 已经把 buildPacket /
   postGateway / deserializeBinary 全封装好，proto-tester 应该薄薄包一层而不是另起炉灶
3. 方案作者偏好 protobuf.js 的核心理由是"运行时灵活、改 proto 不用重新生成"
   但这恰好与项目"协议编号注册表 + 强类型 .ts 文件"的规范相反
   协议改动本来就该走"改 proto → 重新生成 → 改注册表 → 评审"的强约束流程
4. 放弃运行时解析能力意味着放弃"用户手动粘贴未注册 .proto 文件"

```

```text
- §3.3 protoFormBuilder.ts 完全重写：
  从"protobuf.js root.lookupType + field 反射"改为

- §3.4 EnumSelect 数据来源：
```
