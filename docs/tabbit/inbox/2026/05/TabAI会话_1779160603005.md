## 4.2 MessagePacket 解析

```text

```

不要重复定义 MessagePacket。

处理流程：

1. 反序列化请求 body 为 MessagePacket。

7. 如果 extend 中没有 `requestId`，Gateway 生成。

- 不要用 JSON 作为真实主协议。

## 4.5 Adapter

```text

    → MessagePacket.data
```


# 五、状态码与错误处理

必须遵守项目状态码：

| code | 含义 |
|---:|---|
| 10200 | 成功 |
| 10400 | 请求参数错误 |
| 10401 | 无权限 |
| 10404 | 资源不存在 / 路由不存在 |
| 10415 | Content-Type 不支持，如项目没有该码可暂用 10400 |
| 10429 | 请求过于频繁 |
| 10500 | 内部错误 |
| 10504 | Tars 调用超时 |

要求：

1. 不再使用 `code=0` 表示成功。
2. Tars return = 10200 表示内部调用成功。
3. Tars return != 10200 时，Gateway 返回响应 MessagePacket，extend.code 写对应错误码。
4. Tars client 返回 error 时，不直接暴露底层错误。
5. 内部日志可以记录详细错误。
6. 对外 message 必须稳定、安全、可文档化。

建议实现统一错误响应函数：

```go
func BuildErrorPacket(req *MessagePacket, code int, message string) *MessagePacket
```

如果请求 MessagePacket 解析失败，没有 req，则响应 MessagePacket 使用：

- maxType = 0
- minType = 0
- extend.code = 错误码
- extend.message = 错误说明
- data = empty

# 六、extend 透传

Tars extend 必须包含：

| key | 来源 |
|---|---|
| traceId | MessagePacket.extend 或 Gateway 生成 |
| requestId | MessagePacket.extend 或 Gateway 生成 |
| token | MessagePacket.extend 或 Header |
| caller | MessagePacket.extend 或 Header |
| clientIp | HTTP RemoteAddr / Header |
| maxType | MessagePacket.maxType |
| minType | MessagePacket.minType |
| requestProto | routes.yaml |
| responseProto | routes.yaml |
| authRequired | routes.yaml |
| auditRequired | routes.yaml |
| platform | MessagePacket.platform |

要求：

- key 使用 lowerCamelCase。
- value 统一 string。
- response MessagePacket.extend 必须回传 traceId/requestId/code/message。
- 不信任客户端传入 userId/tenantId，后续由 AuthServer 写入。
