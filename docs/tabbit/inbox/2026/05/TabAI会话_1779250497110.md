### **四、蒸馏不是简单压缩，而是分层提取**

真正有用的蒸馏应该把 Raw 材料拆成几类。

#### **1. 事实**

事实是已经发生、能被文件或命令证明的内容。

例如：

```text
SOLO Web 已生成 2026-05-19 的 4 个产物文件。
Trae 新增了 task-raw-archive Command。
Trae 生成了某个 Raw 归档文件。
git status 显示存在未提交文件。
```

事实不能靠猜。

#### **2. 判断**

判断是主控或执行者基于事实做出的结论。

例如：

```text
SOLO Web 可以生成文件并遵守不提交限制。
Task ID 不适合作为 Raw 层主键。
Raw 层应该使用 Source Record，关联层应该使用 Source Map。
```

判断必须标明来源，尤其要区分：

```text
主控已确认
Trae 建议
模型推断
待确认
```

#### **3. 规则**

规则是后续 AI 必须遵守的稳定约束。

例如：

```text
Raw 层不强制使用 Task ID。
不得把 candidate 关联写成 confirmed。
不得把计划写成已完成。
不得把 mock / TODO / 空实现写成主链路完成。
LLM-WIKI.md 只做 Index，不承载完整正文。
```

规则必须经过主控确认后，才能进入长期 Wiki。

#### **4. 风险**

风险是当前会影响后续工作的隐患。

例如：

```text
Tabbit 导出和 Trae 导出命名体系不同，无法天然对齐。
如果强制 Task ID，会制造假关联。
如果不记录 Raw，后续蒸馏会失真。
```

#### **5. 后续行动**

后续行动是下一步要做什么。

例如：

```text
更新 scheduled knowledge distillation Skill。
新增 daily-distill Command。
修正 task-raw-archive Skill 中 Task ID 强制主键表述。
新增 source-map.md。
```

### **六、关联更新是什么**

关联更新不是把内容直接塞进 `LLM-WIKI.md`，而是维护材料之间的关系。

比如现在有三份材料：

```text
Tabbit 原始方案：TabAI会话_1779206504027.md
Trae 评审记录：评审方案，输出评审意见文档.md
Trae 实施 Raw：TB-20260520-000756-trae-task-raw-archive.trae.raw.md
```

它们文件名完全对不上，但它们实际属于同一条工作流：

```text
方案提出 → Trae 评审 → 主控裁决 → Trae 实施
```

这个关系不应该靠 Task ID 硬拼，而应该写入 Source Map：

```text
RG-20260520-001
  - Tabbit 原始方案
  - Trae 评审文档
  - 主控裁决
  - Trae 实施 Raw
```

并标明关联状态：

```text
manual confirmed
candidate
semantic
exact
```

这就是关联更新。

它的重点是：

```text
不是改 Raw 文件。
不是强行统一文件名。
不是伪造一个共同 Task ID。
而是在 Index 层记录它们之间的关系。
```

### **九、大模型蒸馏和日报的区别**

日报回答的是：

```text
今天做了什么？
哪些通过？
哪些失败？
明天做什么？
```

大模型蒸馏回答的是：

```text
今天产生了哪些可复用知识？
哪些规则需要进入长期记忆？
哪些旧记忆需要修正？
哪些 Raw 材料之间有关联？
哪些结论需要主控确认？
```

所以日报是人看的，蒸馏是后续 AI 和项目知识库看的。

两者可以来自同一批 Raw，但输出目的不同。
