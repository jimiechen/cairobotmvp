### **proto-tester 新增 CLI 模式作为 v1.2 → v2.0 的能力扩展，定位为"Trae Skill 触发的自动化协议验收工具"，与现有 Web UI 模式同源同代码（共享 lib/store），只额外暴露一套命令行入口 + 报告产出器；不另起工程。**

你这一刀切得对——proto-tester 原本只服务"人手联调"，缺了"机器自动跑协议验收"这一段，导致 Trae Skill 想做端到端测试时只能调 curl 或自己写 fetch，重复劳动。把 CLI 加进来后整条链路自洽：人用 UI 调试、Trae Skill 用 CLI 验收、两边共享同一份 protocols.json / messageSchemas / test_users.json，证据格式统一。

但 CLI 模式不是免费午餐——录屏 / 截图 / 切换 gateway / traceId 日志聚合这些需求横跨"测试运行时 + 浏览器渲染时 + 后端日志服务"三层，必须分层落地，否则一定写成一个 4000 行的巨型 CLI 脚本。下面按"目标分层 → 命令矩阵 → 报告产出 → Skill 接入 → 实施补丁"五步给完整方案。

---

### **一、整体定位与边界**

```text
工程名：proto-tester（不另起，与 v1.2 同工程）
模式：双入口
  - Web UI 模式：pnpm --filter proto-tester dev  （v1.2 既有，不变）
  - CLI 模式：    pnpm --filter proto-tester cli  （v2.0 新增）

共享层（同源同代码，禁止分裂）：
  - src/lib/messagePacket.ts       MessagePacket 编解码
  - src/lib/apiClient.ts            axios 实例 + 拦截器
  - src/lib/protoMetadata.ts        协议元数据查询
  - src/data/protocols.json         构建期生成的元数据
  - src/data/test_users.json        测试用户池
  - src/data/endpoints.default.json 默认 endpoint 配置

CLI 独有层（新增 src/cli/）：
  - src/cli/index.ts                CLI 入口（commander 或 yargs）
  - src/cli/commands/               子命令实现
  - src/cli/runner.ts                测试用例运行器
  - src/cli/reporter.ts              报告生成器（截图/视频/日志聚合）
  - src/cli/browser.ts                Playwright 浏览器控制（可选启用）

边界约束（在 v1.2 §1.2 铁律基础上新增）：
  - CLI 模式同样禁止接入业务鉴权（用 test_users.json）
  - CLI 模式禁止直连 Tars，必须走 Gateway
  - CLI 录屏 / 截图证据一律本地化（沿用上一轮 admin E2E 简化决策）
  - CLI 不能成为生产监控工具（仅 dev/test/staging，禁止 prod）
  - CLI 运行时禁止持久化 Token（同 Web UI 模式约束）
```

### **二、CLI 命令矩阵**

#### **能力分层：4 个核心子命令**

```text
pnpm --filter proto-tester cli <command> [options]

命令清单：
  send       发送单次协议请求（最小单元）
  run        运行测试用例集（YAML 驱动）
  capture    带浏览器自动化的录屏/截图模式（Playwright）
  trace      根据 traceId 拉取并聚合服务端日志

全局参数（所有命令共享）：
  --env <name>              环境名（dev/test/staging），不允许 prod
  --gateway <url>           覆盖 endpoints.json 中的 gateway baseUrl
  --user <id>               test_users.json 中的 user id
  --token <jwt>             直接传入 token（绕过 test_users，谨慎使用）
  --output-dir <path>       报告输出目录，默认 ./proto-tester-reports/
  --log-level <level>       silent | info | debug | trace
  --no-color                禁用彩色输出（CI 友好）
```

#### **子命令 1：send 单次发送**

```text
用途：发包冒烟测试 / Skill 链式调用
输入：协议号 + 字段 JSON
输出：响应 JSON + 单次报告

命令格式：
  pnpm cli send \
    --max 2100 --min 2101 \
    --payload '{"name":"张三","langCode":"zh-CN"}' \
    --user user_001

输出（默认 info 级别）：
  ► 协议: 2100/2101 HelloWorldRequest
  ► 用户: 运营张三 (admin)
  ► Gateway: http://localhost:8080
  ► TraceID: 7f3a2b1c-...
  ► 请求大小: 64B
  ► 响应大小: 128B
  ► 耗时: 245ms
  ► 业务码: 10200 (成功)
  ► 详细报告: ./proto-tester-reports/send-2100-2101-20260527-174315.md

报告内容（Markdown）：
  - 元数据（时间 / 用户 / gateway / traceId）
  - 请求 JSON 完整快照
  - 请求 raw hex（MessagePacket 二进制 + data bytes 分段）
  - 响应 JSON 完整快照
  - 响应 raw hex
  - 错误码映射结果（如非 10200）
  - traceId 日志摘要（若 --trace-fetch 启用）

退出码：
  0   业务码 10200
  1   业务码非 10200（业务失败）
  2   传输失败 / 超时 / Gateway 不可达
  3   参数错误 / 协议未注册
```

#### **子命令 2：run 用例集执行**

```text
用途：批量验收 / Trae Skill 端到端跑全部协议
输入：YAML 用例文件
输出：JUnit XML + Markdown 总报告 + 每用例子报告

命令格式：
  pnpm cli run \
    --suite tests/suites/admin-mvp-protocols.yaml \
    --parallel 1 \
    --env test

YAML 用例格式（tests/suites/*.yaml）：

  name: admin-mvp-protocols
  description: Admin MVP 阶段全协议冒烟
  defaults:
    env: test
    user: user_001
    gatewayOverride: null   # 不覆盖
  
  cases:
    - id: hello-001
      name: HelloWorld 正常请求
      protocol: [2100, 2101]
      payload:
        name: "Trae"
        langCode: "zh-CN"
      expect:
        businessCode: 10200
        responseFields:
          - field: "greeting"
            matcher: "regex"
            value: "^你好"
    
    - id: app-config-001
      name: AppConfigsReq 多模块查询
      protocol: [6000, 6001]
      payload:
        moduleKeys: ["hello_cfg", "base_cfg"]
        env: "test"
      expect:
        businessCode: 10200
        responseFields:
          - field: "modules"
            matcher: "minLength"
            value: 2
    
    - id: app-config-002
      name: 无效 moduleKey 应返回 10400
      protocol: [6000, 6001]
      payload:
        moduleKeys: ["non_existent_module"]
      expect:
        businessCode: 10400
        errorMessage:
          matcher: "contains"
          value: "module not found"

输出报告结构：
  ./proto-tester-reports/run-<suite>-<timestamp>/
  ├── junit.xml                       # CI 友好
  ├── summary.md                      # 主报告（含通过率 / 失败用例 / 链接）
  ├── traces-index.json               # traceId 索引（key=caseId, value=traceId）
  └── cases/
      ├── hello-001/
      │   ├── report.md               # 用例详情报告
      │   ├── request.bin             # 原始请求字节
      │   ├── response.bin            # 原始响应字节
      │   ├── request.json
      │   ├── response.json
      │   └── server-trace.json       # 服务端日志（若拉取成功）
      ├── app-config-001/...
      └── app-config-002/...

匹配器（matcher）支持：
  exact         完全相等
  regex         正则匹配
  contains      包含
  minLength     最小长度
  maxLength     最大长度
  exists        字段存在
  jsonPath      JSONPath 取值后比对
```

#### **子命令 3：capture 浏览器自动化录屏**

```text
用途：复杂交互场景（如表单填写 + 多步骤请求）需要视觉证据
机制：CLI 内部启动 Playwright + Chromium 加载 proto-tester Web UI
       通过 data-id 锚点（沿用 admin-web E2E 的命名规范）操作 UI

命令格式：
  pnpm cli capture \
    --scenario tests/scenarios/hello-with-token-switch.yaml \
    --video on \
    --screenshot on

YAML 场景格式（tests/scenarios/*.yaml）：
  
  name: hello-with-token-switch
  steps:
    - action: open
      path: /
    - action: select-protocol
      maxType: 2100
      minType: 2101
    - action: switch-user
      userId: user_001
      screenshot: "01-用户切换完成"
    - action: fill-form
      field: name
      value: "Trae"
    - action: send
      screenshot: "02-发送前"
    - action: wait-response
      timeoutMs: 5000
      screenshot: "03-响应已收到"
    - action: assert
      target: response.businessCode
      matcher: exact
      value: 10200

输出结构：
  ./proto-tester-reports/capture-<scenario>-<timestamp>/
  ├── report.md
  ├── video.webm                      # 整个场景录屏
  ├── screenshots/
  │   ├── 01-用户切换完成.png
  │   ├── 02-发送前.png
  │   └── 03-响应已收到.png
  └── network/
      ├── 0-2100-2101.req.bin
      ├── 0-2100-2101.req.json
      ├── 0-2100-2101.rsp.bin
      └── 0-2100-2101.rsp.json

证据本地化策略（沿用 admin E2E 简化决策）：
  - 视频 + 截图存 proto-tester-reports/ 下，.gitignore 排除
  - 不上传 OSS，不生成 index.json
  - 报告通过相对路径引用截图
```

#### **子命令 4：trace 日志聚合**

```text
用途：拿到 traceId 后聚合 Gateway / Servant / 业务服务日志
依赖：后端 dev-only 日志检索 API（同 v1.2 §3.5 stub 方案）

命令格式：
  pnpm cli trace \
    --id 7f3a2b1c-... \
    --since 5m \
    --output ./trace-7f3a2b1c.md

输出报告（Markdown）：
  ## TraceID: 7f3a2b1c-...
  
  ### 时间线
  | 时间 | 服务 | 级别 | 内容 |
  |---|---|---|---|
  | 17:43:15.123 | proto-tester | INFO | 发送 HelloWorld... |
  | 17:43:15.150 | gateway      | INFO | 路由到 hello-servant |
  | 17:43:15.155 | hello-servant| DEBUG| 处理请求 name=Trae |
  | 17:43:15.180 | hello-servant| INFO | 响应已生成 |
  | 17:43:15.195 | gateway      | INFO | 响应已转发 |
  | 17:43:15.368 | proto-tester | INFO | 收到响应 200 |
  
  ### 异常 / 警告
  （无 / 列出 WARN+ERROR）
  
  ### Servant 调用图
  ```mermaid
  sequenceDiagram
    proto-tester ->> gateway: HelloWorld
    gateway ->> hello-servant: forward
    hello-servant -->> gateway: response
    gateway -->> proto-tester: forward
  ```

后端 API 未就绪时降级：
  - 仅打印 traceId
  - 提示用户手动检索
  - 退出码 4（API 不可达）
```

### **三、Gateway 切换策略**

```text
v1.2 已支持 endpoints.json 多配置，CLI 模式需要更灵活：

优先级（高 → 低）：
  1. --gateway <url> 命令行参数         （单次覆盖）
  2. 环境变量 PROTO_TESTER_GATEWAY      （shell session 覆盖）
  3. --env <name> + endpoints.json 中对应环境
  4. endpoints.json 中 default 配置
  5. endpoints.default.json 内置默认

endpoints.json 扩展为多环境：
  {
    "default": "dev",
    "environments": {
      "dev": {
        "gateway": "http://localhost:8080",
        "helloPath": "/api/hello",
        "logService": "http://localhost:8080/api/dev/trace"
      },
      "test": {
        "gateway": "http://test.gateway.internal:8080",
        ...
      },
      "staging": {
        "gateway": "http://staging.gateway.internal:8080",
        ...
      }
    },
    "blocklist": ["prod"]   // 显式禁用 prod
  }

CLI 启动时校验：
  - 解析 --env / --gateway 后输出实际使用的 baseUrl
  - 若解析结果命中 blocklist → 拒绝启动，退出码 3
  - dev 默认值始终是 localhost，避免误连
```

### **四、Trae Skill 接入设计**

#### **Skill 注册（.trae/skills/proto-tester.yaml）**

```yaml
name: proto-tester
displayName: Proto Tester（协议测试客户端）
version: 2.0.0
description: |
  自动化执行 MessagePacket + Protobuf 协议联调。
  支持单次发送、用例集运行、浏览器录屏、traceId 日志聚合四种模式。

commands:
  - name: send
    description: 发送单次协议请求
    args:
      - name: protocol
        description: 协议号，格式 maxType/minType（如 2100/2101）
        required: true
      - name: payload
        description: 请求字段 JSON
        required: true
      - name: env
        description: 环境名（dev/test/staging）
        default: dev
      - name: user
        description: 测试用户 ID
        default: user_001
    exec: pnpm --filter proto-tester cli send

  - name: run-suite
    description: 运行测试用例集
    args:
      - name: suite
        description: YAML 用例文件路径
        required: true
      - name: env
        default: dev
    exec: pnpm --filter proto-tester cli run

  - name: capture
    description: 浏览器自动化场景执行（含录屏 + 截图）
    args:
      - name: scenario
        description: YAML 场景文件路径
        required: true
      - name: video
        description: 是否录屏（on/off）
        default: "on"
    exec: pnpm --filter proto-tester cli capture

  - name: trace
    description: 根据 traceId 聚合服务端日志
    args:
      - name: id
        description: traceId
        required: true
      - name: since
        description: 时间窗口（如 5m / 1h）
        default: 5m
    exec: pnpm --filter proto-tester cli trace

# 主控可调用 Skill 的限制
constraints:
  envBlocklist: ["prod"]
  maxParallelCases: 4
  maxCasesPerSuite: 100
  timeoutSeconds: 600

# 输出契约（让主控能读懂 Skill 产出）
output:
  format: markdown+junit
  baseDir: ./proto-tester-reports/
  retentionDays: 7
```

#### **Skill 调用约定**

```text
触发场景：
  - 用户："跑一下 hello 协议看看通不通" 
    → Skill 自动执行 send --max 2100 --min 2101 --payload '{}'
  
  - 用户："admin MVP 全协议验收"
    → Skill 执行 run-suite --suite tests/suites/admin-mvp-protocols.yaml
  
  - 用户："录一个登录后查配置的视频"
    → Skill 执行 capture --scenario tests/scenarios/login-and-fetch-config.yaml
  
  - 用户："这个 traceId 7f3a... 查一下后端日志"
    → Skill 执行 trace --id 7f3a... --since 10m

返回约定：
  - 退出码 0  → 成功，Skill 报告路径回灌给主控
  - 退出码非 0 → 失败，Skill 摘要 stderr 关键行 + 报告路径回灌
  - 主控基于 junit.xml 或 summary.md 做下一步决策（如自动修复 / 通知用户）

调用频率：
  - 同一 suite 5 分钟内不允许重复触发（缓存上次结果）
  - capture 模式因消耗资源大，需用户显式确认
```
