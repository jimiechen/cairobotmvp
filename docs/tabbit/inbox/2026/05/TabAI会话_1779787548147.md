#### **🔴 问题 2：redisx.Invalidate(pattern) API 不存在**

**实现要求：**

```go
// go/third_party/redisx/redisx.go
func (c *Client) Invalidate(ctx context.Context, pattern string) error {
    keys, err := c.Scan(ctx, pattern)
    if err != nil {
        return fmt.Errorf("redisx invalidate scan: %w", err)
    }
    if len(keys) == 0 {
        return nil
    }
    // 大批量分片删除，避免一次性 DEL 过多 key 阻塞 Redis
    const batchSize = 500
    for i := 0; i < len(keys); i += batchSize {
        end := i + batchSize
        if end > len(keys) {
            end = len(keys)
        }
        if err := c.Delete(ctx, keys[i:end]...); err != nil {
            return fmt.Errorf("redisx invalidate delete: %w", err)
        }
    }
    return nil
}
```

**测试覆盖：**

```text

- 单 key
- 多 key（< 500，单批）
- 多 key（> 500，分批）
- Scan 失败
- Delete 失败
- ctx 取消传播
覆盖率 ≥80%
```

```go
// services/config/admin/schema_service.go
type AdminSchemaService struct {
    inner   *service.SchemaService    // 复用校验/组装
    repo    domain.SchemaRepository
    cache   redisx.Client
    bus     redisx.PubSubClient
    audit   audit.Logger
}

func (s *AdminSchemaService) Create(ctx context.Context, req CreateSchemaDTO) error {
    // 1. DTO → domain
    schema := req.ToDomain()
    
    // 2. 复用 service 层校验（不重写）
    if err := s.inner.Validate(ctx, schema); err != nil {
        return ErrValidation.Wrap(err)
    }
    
    // 3. 落库
    if err := s.repo.Create(ctx, schema); err != nil {
        return err
    }
    
    // 4. 审计日志
    s.audit.Log(ctx, "create_schema", schema)
    
    // 5. 失效缓存
    pattern := fmt.Sprintf("config:schema:%s:*", schema.TenantID)
    if err := s.cache.Invalidate(ctx, pattern); err != nil {
        log.Warnw("invalidate failed", "err", err)
        // 不阻塞主流程
    }
    
    // 6. 广播
    payload := buildInvalidateEvent(schema)
    if err := s.bus.Publish(ctx, "cairobot.config.invalidate", payload); err != nil {
        log.Warnw("publish failed", "err", err)
    }
    
    return nil
}
```

#### **🟡 9 的具体方案（CSV 导入两阶段）**

```text
阶段一：Dry-Run（无事务，全量校验）
  - 解析 CSV → 内存中构造 100 条 LangString
  - 逐条调用 service 层 Validate（不写库）
  - 收集所有错误
  - 任一错误 → 返回行级错误列表，不进入阶段二

阶段二：事务写入（仅 dry-run 全部通过才执行）
  - 单事务批量插入
  - 单事务上限 100 条（超限自动分批）
  - 任一行写入失败 → 整个事务回滚
  - 回滚后写入审计日志（记录失败原因）

性能保障：
  - dry-run 用内存校验 + sqlx Prepare 缓存，100 条 ≤ 500ms
  - 事务写入批量 INSERT VALUES，100 条 ≤ 1s
  - 总计 ≤2s 满足约束
```
