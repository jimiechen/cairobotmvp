### **要补一条硬规则：Trae 每次执行任务，都必须把“任务输入 + 执行结果 + 产物清单”沉淀到 Raw 层。**

这个需求是对的，而且应该上升为 LLM Wiki 三层结构里的基础规则，不是可选项。

现在三层结构如果只记录 SOLO Web 的每日产物，而不记录 Trae 每次实际执行的任务上下文，那么后续蒸馏会丢掉最重要的一层事实来源：**任务提示词、执行过程结论、实际产物**。这样 Distillation 层就会变成“只看结果，不知道任务是怎么被要求的”，知识会失真。

所以应该新增一条规则：

```text
所有由 Trae 执行的任务，都必须先归档到 Raw 层。
Raw 层必须至少包含：
1. 任务提示词 / 用户原始要求
2. Trae 的执行结果摘要
3. 本次任务生成或修改的产物清单
4. 若有命令执行，则记录关键命令与结果摘要
5. 若有主控裁决，则记录主控结论或待确认项
```

---

### **这条规则的意义**

这条规则解决的是“知识失真”问题。

如果只保存最终日报、最终蒸馏，后续 AI 会看不到：

- 这次任务原本要做什么
- 哪些是用户要求
- 哪些是 Trae 自行补齐
- 哪些内容真正产出了文件
- 哪些只是分析，没有落盘
- 哪些结论已经确认，哪些还只是候选

所以 Raw 层应该成为“任务事实底账”。

### **应该做成 Skill 还是 Command**

这里最好 **Skill + Command 都做**，但职责不同。

#### **Skill 的职责**
Skill 负责定义规范，让 AI 助手知道“任何 Trae 任务都必须先落 Raw 层”。

建议新增或补充一个 Skill，例如：

```text
.trae/skills/cairobot-task-raw-archive.md
```

它负责定义规则：

- 什么任务必须归档
- Raw 层必须记录哪些内容
- 记录格式是什么
- 哪些内容不能省略
- 什么情况下允许只记录摘要
- 什么情况下必须完整记录提示词

#### **Command 的职责**
Command 负责给 Trae 一个稳定入口，执行“任务归档”动作。

建议新增 Command：

```text
.trae/commands/task-raw-archive.md
```

或者更贴近你的三层体系命名：

```text
.trae/commands/llm-raw-task.md
```

它的用途是：

- 输入本次任务说明
- 自动整理为 Raw 层文件模板
- 输出建议的 Task ID
- 列出产物清单
- 提示是否需要继续蒸馏到 Distillation 层

### **最终结论**

你这个要求应该直接纳入三层知识库硬规则：

```text
Trae 每次执行任务，必须先在 Raw 层留痕。
必须记录任务提示词、任务结果、任务产物。
没有这些，Distillation 层就不可信。
```

所以我建议最终落地为：

- 一个新 Skill：规范所有 Trae 任务必须归档 Raw
- 一个新 Command：标准化执行任务 Raw 归档
- 更新 `任务索引.md`
- 更新 `llm-wiki-three-layer-architecture.md`
- 更新 `llm-wiki-architecture.md`

这条规则非常关键，因为它把“AI 做过什么”变成了可追溯的工程资产。
