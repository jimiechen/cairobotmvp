### **二、Hello 模块升级方案**

#### **2.1 当前状态**

```text
HelloReq  { name }
HelloRsp  { result, message="Hello, {name}!" }
```

字符串硬编码，不演示任何 SDK 接入。

#### **2.2 升级后的语义**

```text
HelloReq  { name, lang_code }
HelloRsp  { result, greeting, server_name, max_name_length }

行为：
1. greeting：通过 i18nsdk 渲染
   key = svc_hello_greeting
   template_type = named
   params_schema = [{name, string, required}]
   zh-CN: "你好，{name}！欢迎使用 {server_name}。"
   en:    "Hello, {name}! Welcome to {server_name}."

2. server_name：通过 configsdk 读取
   module_key = hello_cfg
   field_key  = server_name
   type       = string
   default    = "CaiRobot"

3. max_name_length：通过 configsdk 读取
   module_key = hello_cfg
   field_key  = max_name_length
   type       = int
   default    = 32
   作用：服务端先用此值做长度校验，超长返回 10400
```

#### **2.3 文件结构**

```text
go/modules/hello/
├── service.go           # 主入口，仅做依赖装配，≤80 行
├── handler.go           # ModuleHandler 实现：解码请求 → 调业务 → 编码响应，≤120 行
├── usecase.go           # 业务逻辑：组合 configsdk + i18nsdk，≤150 行
├── usecase_test.go      # 单元测试（用 SDK fake）
└── README.md            # 模块文档（接入规范的活样板）
```

#### **2.4 关键代码骨架**

```go
// go/modules/hello/usecase.go
package hello

type Usecase struct {
    cfg  configsdk.Client
    i18n i18nsdk.Client
}

func NewUsecase(cfg configsdk.Client, i18n i18nsdk.Client) *Usecase {
    return &Usecase{cfg: cfg, i18n: i18n}
}

func (u *Usecase) Greet(ctx context.Context, req *pb.HelloReq) (*pb.HelloRsp, error) {
    // 1. 配置驱动的校验
    maxLen, err := u.cfg.GetInt(ctx, "hello_cfg", "max_name_length")
    if err != nil { return nil, err }
    if int64(len(req.Name)) > maxLen {
        return errResp(codes.BadRequest, "name too long"), nil
    }

    // 2. 配置驱动的服务名
    serverName, err := u.cfg.GetString(ctx, "hello_cfg", "server_name")
    if err != nil { return nil, err }

    // 3. i18n 渲染
    lang := req.LangCode
    if lang == "" { lang = "zh-CN" }
    greeting, err := u.i18n.T(ctx, lang, "svc_hello_greeting", map[string]any{
        "name":        req.Name,
        "server_name": serverName,
    })
    if err != nil {
        // 降级文案
        greeting = "Hello, " + req.Name + "!"
    }

    return &pb.HelloRsp{
        Result:        okResult(),
        Greeting:      greeting,
        ServerName:    serverName,
        MaxNameLength: int32(maxLen),
    }, nil
}
```

注意三点：

```text
- usecase 不直接 import services/config / services/i18n 内部包
- 所有 SDK 调用都带 ctx，便于追踪
- i18n 渲染失败时降级，不抛异常
```

#### **2.5 Schema 注册（首启自动注入）**

为避免"光有代码没有数据"，模块启动时通过 admin-server API 或 SQL 迁移脚本注入默认 schema：

```text
sys_config_schema 注入：
  module_key=hello_cfg, field_key=server_name,
    type=string, default="CaiRobot", scope=all
  module_key=hello_cfg, field_key=max_name_length,
    type=int, default=32, validator='{"min":1,"max":256}', scope=all

sys_lang_string 注入：
  key=svc_hello_greeting, template_type=named,
    params_schema=[{name,string,required},{server_name,string,required}],
    zh-CN: "你好，{name}！欢迎使用 {server_name}。"
    en:    "Hello, {name}! Welcome to {server_name}."
```

迁移脚本放在 `migrations/seed/hello_seed.sql`，与代码一同发布。

### **三、Health 模块升级方案**

#### **3.1 当前状态**

```text
HealthCheckReq  {}
HealthCheckRsp  { result, status, version }
```

只返回 OK，无业务上下文。

#### **3.2 升级后的语义**

```text
HealthCheckReq  { lang_code, depth }
HealthCheckRsp  { result, status, version, message, components[] }

行为：
1. status：自身存活检查（永远 OK，进程活着才能响应）

2. components[]：依赖健康检查
   - mysql   通过 mysqlx.Ping
   - redis   通过 redisx.Ping
   - config  通过 configsdk.Ping
   - i18n    通过 i18nsdk.Ping
   每项返回 { name, status, latency_ms, error }

3. message：人性化文案，i18nsdk 渲染
   key = svc_health_status_summary
   template_type = icu
   params_schema = [{healthy,int},{total,int}]
   zh-CN:
     "{healthy, plural,
        =0 {所有依赖均不可用（{total} 项）}
        other {# / {total} 项依赖正常}
      }"
   en:
     "{healthy, plural,
        =0 {All {total} dependencies are down}
        other {# of {total} dependencies healthy}
      }"

4. version：通过 configsdk 读取
   module_key = system_cfg
   field_key  = build_version
   type       = string
   default    = "0.0.0-dev"

5. depth：
   - depth=0 仅自身存活
   - depth=1 依赖 ping
   - depth=2 依赖 + 一次实际查询（如 SELECT 1）
   通过 configsdk 控制最大允许 depth：
     hello_cfg / health_cfg.max_depth
```

#### **3.3 文件结构**

```text
go/modules/health/
├── service.go           # ≤80 行
├── handler.go           # ≤120 行
├── usecase.go           # 主流程 ≤120 行
├── checker.go           # 各依赖检查器（mysql/redis/config/i18n），≤150 行
├── usecase_test.go
└── README.md
```

`checker.go` 用接口隔离，业务模块复用：

```go
type Checker interface {
    Name() string
    Check(ctx context.Context) ComponentStatus
}

type ComponentStatus struct {
    Name      string
    Healthy   bool
    LatencyMs int64
    Error     string
}
```

后续每个业务模块的 health 子模块只需实现 `Checker`，注册到统一 health 模块即可，**不再各自重复造轮子**。

### **四、统一接入规范（这是本次的真正交付物）**

把 Hello / Health 升级过程中沉淀下来的规则，写成 `docs/wiki/modules/sample-module.md`，作为后续所有业务模块的标准模板。

#### **4.1 模块标准目录结构**

```text
go/modules/<name>/                ← 业务模块（被 Gateway 路由调用）
├── service.go                    依赖装配，输出 *Service 单例
├── handler.go                    bytes ↔ proto 转换 + 路由分发
├── usecase.go                    业务逻辑（多个，按用例命名）
├── checker.go                    可选：health 检查器
├── *_test.go                     单元测试，覆盖率 ≥80%
└── README.md                     模块文档（含 schema/i18n key 清单）
```

#### **4.2 模块依赖装配标准签名**

所有业务模块的 service.go 都遵循统一 New 函数签名：

```go
func New(deps Deps) *Service

type Deps struct {
    Config configsdk.Client     // 必选
    I18n   i18nsdk.Client       // 可选（无文案场景为 nil）
    DB     *mysqlx.DB           // 可选（无持久化为 nil）
    Cache  *redisx.Client       // 可选
    Logger *log.Logger          // 必选
}
```

main.go 中统一装配：

```go
deps := module.Deps{
    Config: configsdk.Default(),
    I18n:   i18nsdk.Default(),
    DB:     mysqlx.Default(),
    Cache:  redisx.Default(),
    Logger: log.Default(),
}
helloSvc  := hello.New(deps)
healthSvc := health.New(deps)
```

任何业务模块**禁止**自己直接 import services/config 内部包、禁止自己 sql.Open、禁止自己 redis.NewClient。

#### **4.3 配置接入约束**

```text
1. 任何配置读取必须通过 configsdk
2. module_key 命名：<模块名>_cfg（如 hello_cfg、device_cfg、openapi_cfg）
3. 配置字段必须先在 sys_config_schema 注册后才能读取
4. 启动时 SDK 调用 GetInt/GetString 不应阻塞主流程：
   - 读不到时降级到 default（schema 提供）
   - 仅记录 warn 日志，不抛异常
5. 热更场景使用 Watch 订阅，不要在每次请求里轮询
```

#### **4.4 多语言接入约束**

```text
1. 任何用户可见文案必须通过 i18nsdk.T() 渲染
2. key 命名：svc_<模块名>_<场景>（如 svc_hello_greeting、svc_health_status_summary）
3. 服务端 T() 仅用于：推送、短信、邮件、Webhook、错误响应文案
4. 客户端可渲染的场景使用 Raw()，由客户端按 template_type 渲染
5. 任何 T() 调用必须有降级文案（fallback string），不允许直接抛错
6. 必须在 sys_lang_string 中注册中英文两条记录，否则 CI 拒绝合入
```

#### **4.5 Health 接入约束**

```text
1. 每个模块若涉及外部依赖，必须实现 Checker 并注册到 health 模块
2. checker 的 Check() 必须有超时（默认 1s），不能拖垮 health 协议
3. 失败状态写入 ComponentStatus.Error 字段，便于运维定位
```

#### **4.6 测试接入约束**

```text
1. usecase_test.go 必须用 SDK fake，不依赖真实 Redis / MySQL
2. 集成测试用 build tag = integration
3. 模块覆盖率必须 ≥80%
4. 每个模块必须有一个端到端用例（gateway → handler → usecase → SDK → 返回）
```

#### **4.7 文档接入约束**

每个模块 README.md 必须包含 6 节：

```text
1. 模块职责（一句话）
2. 协议清单（maxType/minType + req/rsp message）
3. 配置 Schema 清单（module_key + 字段表）
4. 多语言 Key 清单（key + 各语言模板）
5. 依赖关系（依赖哪些 SDK / 基础设施）
6. 健康检查（Checker 实现说明）
```
