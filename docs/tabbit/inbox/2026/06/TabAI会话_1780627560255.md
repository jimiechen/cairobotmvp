### **五、auth_required 纳入用例生成规则**

原方案中 Config/I18n 正向用例没有明确 Token 前置条件，这是评审指出的 P1 问题。新版规则如下：

```text
生成 E2E-CASE-MATRIX.md 时，必须按 auth_required 分组。

规则：

1. auth_required=false
   - 正向用例不需要 Token。
   - 仍然可以附带 Token，但不能依赖 Token 才通过。
   - 缺失 Token 不应导致 401/403。

2. auth_required=true
   - 正向用例必须携带有效 Bearer Token。
   - 必须额外生成两个负向用例：
     a. 缺失 Token
     b. 错误 Token
   - 正向用例 expected.httpStatus 不能写 200，除非确认 Token 注入成功。
   - 负向用例 expected 应为项目实际定义的 401/403 或业务错误码。

3. 报告中每个用例必须包含：
   - auth_required
   - token_required: true/false
   - token_source
   - token_redacted: true
```

#### **修订后的 Config 用例模板**

### **六、协议 maturity 纳入优先级和结论规则**

评审指出 `protocols.json` 中部分协议处于草案状态，原方案直接标 P0 可能不稳。新版规则如下：

```text
请在 E2E-DISCOVERY.md 和 E2E-CASE-MATRIX.md 中增加 maturity 字段。

maturity 取值来自 protocols.json 的 status 字段：
- enabled / 已启用
- draft / 草案
- deprecated / 废弃
- unknown / 未知

判定规则：

1. 已启用协议
   - 可以进入 MVP 必选集。
   - 服务可运行时，失败判 FAIL。

2. 草案协议
   - 如果服务端 Handler 已实现，且 Gateway 路由存在，可以进入 MVP 扩展集。
   - 如果服务端 Handler 未实现，标记 BLOCKED。
   - 草案协议失败时，需要区分：
     a. 协议生成错误：FAIL
     b. 服务未实现：BLOCKED
     c. 路由未接入：BLOCKED

3. 废弃协议
   - 不进入 MVP 必选集。
   - 仅进入完整回归集中的兼容性用例。

4. unknown
   - 不允许直接作为 P0。
   - 必须补充协议来源说明。
```

用例矩阵增加字段：

```markdown
| Case ID | Route | max:min | Protocol | Maturity | auth_required | Mode | Priority | Expected | Status |
|---|---|---:|---|---|---|---|---|---|---|
```

### **十四、修订后的验收判定门禁**

```text
验收判定规则：

1. Preflight 门禁
   - 如果 Gateway 实际加载 routes.yaml 不明确：BLOCKED
   - 如果 /api/hello 不存在且没有替代入口：BLOCKED
   - 如果 proto-tester CLI 不可运行：BLOCKED
   - 如果协议元数据无法生成或读取：BLOCKED

2. MVP 必选集门禁
   - 已启用协议的 P0 用例必须 PASS。
   - auth_required=true 的正向用例必须携带有效 Token。
   - auth_required=true 的缺失 Token / 错误 Token 用例必须返回稳定鉴权错误。
   - traceId 至少必须贯穿 proto-tester、Gateway receive、Gateway route、Service handler 或等效处理层。
   - request.raw.json 和 response.raw.json 缺失时，该用例不得判 PASS。

3. 草案协议处理
   - 草案协议如果 Handler 已实现，可以参与验收。
   - 草案协议如果 Handler 未实现，标记 BLOCKED。
   - 草案协议不得因为服务未实现直接判 FAIL。

4. TarsGo 模式处理
   - TarsGo 环境完整可用时执行 TarsGoInvoker E2E。
   - TarsGo 环境不完整时标记 BLOCKED。
   - 只能运行 go/tars/*/e2e_test.go 时，只能作为子链路证据，不能等同于完整 Gateway E2E。

5. 最终结论
   - MVP 必选集全部 PASS，且无 P0 BLOCKED：验收 PASS。
   - MVP 必选集存在 P0 FAIL：验收 FAIL。
   - MVP 必选集存在 P0 BLOCKED：验收 BLOCKED。
   - 完整回归集中的 P1/P2 问题可作为后续修复项，但必须记录。
```
