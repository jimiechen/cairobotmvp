### 架构领域

4. **TarsGo 网关架构口径正式修正**
   - local 模式 = TarsGo 单体部署模式，使用 TarsGo 框架运行（TarsHttpMux / AddHttpServant / Run）
   - local 模式不是"不使用 Tars"，而是不连接远程 TarsCloud 注册中心
   - LocalInvoker = 本进程 TarsGo servant adapter，不绕过 Tars 框架
   - TarsGoInvoker = 微服务部署模式下的远程 TarsGo client invoker（S1 阶段实现）
   - proto-gateway 身份 = TarsGo HTTP Servant

5. **两种部署模式的共同点**
   - 都使用 TarsGo 框架运行
   - 都遵守 Tars bytes 契约
   - 区别仅是部署拓扑（同进程 vs 跨进程）

1. **Raw 层目录边界**：`docs/wiki/` 只承载 Distillation 层和 Index 层，Raw 层内容一律放在 `docs/tabbit/inbox/`、`docs/trae-export/inbox/`、`docs/reports/daily/`、`docs/reports/testing/` 等位置。不得在 `docs/wiki/` 下创建 raw/ 子目录。

2. **Trae 任务 Raw 归档路径**：`docs/trae-export/inbox/tasks/YYYY/MM/{TASK_ID}.trae.raw.md`，TASK_ID 格式 `TB-{YYYYMMDD}-{HHMMSS}-{slug}`。

3. **Raw 归档与任务汇报的关系**：Raw 归档是"任务完成汇报"的结构化持久化版本，不是额外重复工作。Command 应复用汇报内容生成 Raw 文件。

4. **TarsGo 网关架构口径**：
   - local 模式 = TarsGo 单体部署（用 TarsGo 框架，不连注册中心）
   - LocalInvoker = 本进程 TarsGo servant adapter（不绕过 Tars 框架）
   - TarsGoInvoker = 远程 TarsGo client（S1 阶段实现）
   - 两种模式的共同点：都用 TarsGo 框架、都遵守 Tars bytes 契约、区别仅是部署拓扑

5. **MVP 阶段单 Command 原则**：对于新流程，优先实现单一 Command，验证价值后再考虑拆分多阶段。
