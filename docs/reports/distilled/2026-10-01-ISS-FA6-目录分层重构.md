## 2. 新增事实

- fa_orchestrator 包内目录从 28 文件平铺重构为六层职责分层：
  graph/（图编排内核 4）+ agents/（分析决策 Agent 7）+ analysis/（分析引擎 4）+
  data/（数据接入 5）+ infra/（基础设施 2）+ report/（报告输出 2），
  包根保留入口层（__init__/__main__/cli/cli_trace）与 configs/。
- 六个子包各含带中文职责边界注释的 `__init__.py`，注释引用 PRD-12 与 ADR-017。
- import 路径批量重写 76 处/38 文件 + 手工修正 3 处；git mv 保留文件历史。
- 包外零代码依赖 fa_orchestrator 模块路径（全仓扫描确认），重构影响面封闭在包内与测试。

## 3. 决策

- 分层方案经 AskUserQuestion 用户确认：A 方案六层职责分层（推荐项），
  CLI 留包根（cli_trace 的 yaml 路径锚点与 5 个测试文件的 import 路径不变，diff 最小），
  report_agent 归入 report/ 输出层（与 html_report 构成同一报告输出链路）。
- configs/ 留包根：测试用 `_PKG/"configs"` 定位 yaml，包根锚定使测试零路径改动。
- match_review 归 analysis/ 而非 agents/：它是 CLI 直调的赛后复盘模块，
  不注册进 agent_registry，语义上属"赛前分析 + 赛后复盘"的分析引擎层。
- 测试文件不迁移：tests/ 已按 integration/safety-cases/fixtures 分组，
  不移动则测试用例注册表零改动（make rules 保持全绿）。
