# ADR-018: FA 欧赔全序列输出（euro.history）采用附加键向后兼容方案

## 状态

已接受（2026-10-13，主控批准方案 B；立项评审见
[docs/drafts/立项评审-欧赔全序列输出-20261013.md](../drafts/立项评审-欧赔全序列输出-20261013.md)）

## 背景

2026-10-12 读取完整性探查（PRD-12 方案 A 后续）发现：workbench 库内欧赔
（odds_europe）存在大量中间调整状态——2026-10-08 竞彩日各公司 4~40 个独立
赔率状态（2951 澳门 40 态、2949 澳门 22 态），而 mysql 通道 `pair_odds`
归并只输出初盘 + 即时盘 2 态，降水/升赔路径全部丢失。

关键事实：

- **SQL 层无缺口**：`SQL_Q3_EUROPE` 本就返回全部快照行（按公司 + 快照时间
  排序），缺口仅在 parse 层归并函数
- **消费端零依赖**：OddsVerifyAgent / SynthesisAgent 只读 euro 行的
  `bk / payout / initial / current`，无任何模块消费中间态
- 目标口径（主控 2026-10-12 确立）：库内已有数据 100% 进入分析，降级仅保留
  "库里真没有"

## 决策

1. **输出结构**：euro 行附加 `history` 键（超集扩展，向后兼容）——
   `[{win, draw, lose, payout, snapshot_time}, ...]` 全状态序列
2. **归并口径**（`history_states` 纯函数）：
   - 按赔率值元组保序去重；序按各态**首次出现**定序
   - 每态 payout / 快照时间取该态**末次**出现行（回摆态时间即回摆时点）
   - 首态=初盘；末态=最后新增态——最新赔率回摆历史态时 current 对应
     history 中间项（真实库 2951 澳门实况，非缺陷）
3. **启用范围**：仅欧赔（Q3 euro）；亚盘/大小盘库内独立状态基本 ≤2（重复
   快照为主），变盘方向已由 D9 多公司轨迹覆盖，不加 history
4. **分两期**：
   - 本期（已实施）：数据完备性——parse 层 history 输出 + fixture 契约同步
   - 二期（另立 Issue）：OddsVerifyAgent 消费条款（降水路径/临场异动信号），
     随 v7.x SKILL 评审后实施

## 后果

- 正：库内欧赔序列 100% 进入分析产物；为二期降水路径分析提供数据基座；
  SQL 零改动；旧消费端零影响
- 负：产物体积增长（单场 euro history 最大 40 态/公司，standalone 报告
  体积随之上升）；本期无消费方（数据先行，防"以后再补"跳过）
- 中性：payout 数值口径与库一致透传（库为 88.9 百分比形式，fixture 模拟值
  为 0.905 比率形式），消费端使用时统一

## 替代方案

- A 暂缓（维持两态 + 缺口标注）：与既定目标相悖，数据已在 SQL 返回中丢弃——否决
- C 全重构（pair_odds 输出改全序列结构）：破坏 fixture 唯一契约、消费端
  全面联动——否决

## 实施记录（本期）

- TDD：红（KeyError: history）→ 绿 → 全量 383 passed, 4 skipped
- 真库验证（只读）：history 态数与库内独立状态数逐场一致（2951 澳门 40 等），
  首态=初盘、回摆语义如上
- fixture 同步：28 行 euro 补 history、2 处 bf 补 large_volume（必发全类型
  改造的契约欠账一并补齐）
