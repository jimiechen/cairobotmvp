## 3. 决策

采用多系统、多技术栈的微服务架构：

1. **系统划分**：
   - 服务商后台系统
   - 终端用户中台系统
   - 开放平台 API
   - AI 服务系统
   - 设备通信网关
   - API 网关
   - 认证服务
   - 审计服务

2. **技术栈**：
   - 后端核心：Golang
   - 服务协议：Protobuf + gRPC
   - AI 服务：Python
   - 前端：ReactJS

3. **协议层**：
   - 内部服务通信：gRPC + Protobuf
   - 开放平台对外：HTTPS JSON + OpenAPI
   - 统一契约来源：Protobuf

## 6. 后果

### 6.1 正面
- 系统职责清晰，易于扩展
- 多技术栈各取所长
- 协议统一，减少沟通成本

### 6.2 负面
- 系统复杂度增加
- 部署运维复杂度上升
- 跨语言调用有一定开销

## 7. 约束

- 所有服务间通信优先使用 gRPC + Protobuf
- 开放平台 API 必须通过协议转换暴露
- Protobuf 定义统一放在根目录 proto/ 下
