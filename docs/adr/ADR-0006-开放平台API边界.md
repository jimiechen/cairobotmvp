## 3. 决策

开放平台 API 必须与内部服务解耦，通过协议转换层对外暴露 HTTPS JSON 接口。

## 4. 理由

（待补充）

## 5. 替代方案

- 直接暴露内部 gRPC 接口
- 使用 GraphQL 对外

## 6. 后果

### 6.1 正面
- 内部实现可以自由演进
- 对外接口可以独立版本管理
- 安全性更好控制

### 6.2 负面
- 增加协议转换层复杂度
- 需要维护两套接口（内部 gRPC + 对外 JSON）

## 7. 约束

- 开放平台 API 必须通过协议转换层
- 不能直接暴露内部数据库或内部服务实现
- 必须有 API Key / Token 鉴权
- 必须有调用频率限制
- 必须有审计日志

## 8. 后续待确认事项

- API 版本管理策略
