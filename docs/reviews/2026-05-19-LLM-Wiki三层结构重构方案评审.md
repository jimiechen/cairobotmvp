## 一、结论

方案整体设计合理、方向正确、约束清晰，但存在 **3 个必须修改项** 和 **4 个建议修改项**，修改后方可进入执行阶段。

## 二、符合要求的部分

### 2.1 方向判断正确

1. **SOLO Web 职责边界划分合理**：明确 SOLO Web 做"每日自动化执行者"而非"结构性重构者"，这个分工符合工具能力边界。
2. **三层架构设计合理**：Raw → Distillation → Index 的分层逻辑清晰，解决了 LLM-WIKI.md 无限膨胀的根本问题。
3. **禁止事项覆盖全面**：10 条禁止 + 10 条允许的边界定义清晰，可有效防止执行越界。
4. **验收口径务实**：不只看"文件有没有创建"，而看"结构是否真正变了"，这是正确的工程评审视角。

### 2.2 与现有体系兼容

1. **Skill 格式一致**：方案要求参考已有 Skill 格式，与现有的 12 个 Skill（如 `cairobot-daily-report`、`tabbit-task-distillation`）的 YAML frontmatter + Markdown 结构兼容。
2. **Command 格式一致**：与已有的 `/tabbit-task` Command 的结构化指令风格一致。
3. **不破坏已有归档流程**：新方案不冲突 ADR-0009 的 Tabbit 归档流程和 Canonical Task ID 体系。
4. **目录规范符合 docs.md 规则**：新增目录均在 `docs/wiki/` 下，未违反文档存放规则。

### 2.3 任务拆分合理

将任务分为 10 个子任务（LLM-WIKI.md 重构 → 索引建立 → ADR 沉淀 → 模块文档 → Skill → Command → README → 验收），粒度适当，每个子任务目标明确。

## 三、必须修改项

### 3.1 🔴 P0: SOLO Web 试运行产物不存在

**问题描述**：

方案中多次引用以下 4 个文件作为已验证的事实依据：

```
docs/reports/daily/2026-05-19-SOLO-Web试运行原始记录.md
docs/reports/daily/2026-05-19-每日日报.md
docs/reports/distilled/2026-05-19-每日知识蒸馏.md
docs/reports/daily/2026-05-19-主控汇报.md
```

但实际仓库中 **这 4 个文件全部不存在**。`docs/reports/daily/` 下只有：
- `2026-05-17-HelloWorld验收日报.md`
- `2026-05-18-HelloWorld验收日报.md`
- `日报模板.md`

`docs/reports/distilled/` 下只有 `每日蒸馏模板.md`。

**影响**：
- 方案第 22-26 行声称"本次试运行已生成以下 4 个文件"，与仓库事实不符。
- 第 116-118 行要求读取这些文件作为必须先读材料，执行时会报"缺失"。
- 第 196 行索引表和第 216 行任务表引用了这些不存在的文件路径。
- 基于不存在文件的"主控裁决"缺乏事实基础。

**修改建议**：
- 方案中应标注这些文件为"预期产物"而非"已生成产物"。
- 或者先确认 SOLO Web 是否确实运行过并生成了这些文件——如果尚未运行，则应调整方案措辞为"待 SOLO Web 执行后确认"。
- 如果 SOLO Web 已在外部生成但未入库，需先将文件放入对应目录后再执行本方案。

### 3.2 🔴 P0: LLM-WIKI.md 重构范围需要更精确的迁移指引

**问题描述**：

当前 [LLM-WIKI.md](../wiki/LLM-WIKI.md) 共 308 行，包含以下内容类型：

| 行范围 | 内容 | 应归属层级 |
|---|---|---|
| 1-5 | 标题和定位 | Index 层（保留摘要） |
| 6-37 | 项目定位 + 系统组成 | Distillation 层（模块知识） |
| 38-98 | 阶段 + 优先级 + 已完成/未完成事项 | Index 层（保留摘要+链接）或 Distillation 层 |
| 99-145 | TDD 与 CI 规则 | Distillation 层（模块知识）或已有 rules 引用即可 |
| 149-175 | Protobuf 协议核心规则 | CODE-WIKI.md 已有重复内容 |
| 177-196 | 关键目录说明 | Index 层（导航） |
| 197-303 | 各类索引（PRD/ADR/测试/Bug/事故/蒸馏/Tabbit任务） | Index 层（保留链接） |
| 304-308 | AI 助手规则 | Index 层（保留摘要） |

方案要求"将 LLM-WIKI.md 改造成 Index 层入口"，但没有给出 **逐段迁移映射表**。执行者需要知道：
- 哪些段落直接删除？
- 哪些段落压缩为摘要？
- 哪些段落移动到哪个新文件？
- CODE-WIKI.md 中已重复的内容如何处理？

**修改建议**：
在方案的"一、重构 docs/wiki/LLM-WIKI.md"部分增加一个迁移映射表，例如：

```markdown
| 原 LLM-WIKI.md 章节 | 目标操作 | 目标位置 |
|---|---|---|
| §2 系统组成（7 个系统描述） | 压缩为 7 行摘要 + 链接 | LLM-WIKI.md（Index）→ 详情移至 modules/system-overview.md |
| §5 已完成事项（30+ 条 checkbox） | 替换为一句话统计 + 链接到完整列表 | LLM-WIKI.md（Index） |
| §7 工程级 TDD 与 CI 规则 | 删除正文，替换为 "详见 .trae/rules/tdd.md" | LLM-WIKI.md（Index） |
| §8 Protobuf 协议核心规则 | 删除（CODE-WIKI.md §4 已完整覆盖） | 无 |
| §15 Tabbit / TRAE 任务归档索引 | 保留但精简，详情由 每日蒸馏索引.md 承载 | LLM-WIKI.md（Index） |
```

### 3.3 🔴 P1: 新增 Skill 名称与 AGENTS.md Skill 索引不同步

**问题描述**：

方案要求新增 `.trae/skills/cairobot-llm-wiki-distillation.md`，但 [AGENTS.md §19.1](../../AGENTS.md) 的 Skill 索引表中没有预留此 Skill 的条目。如果新增此 Skill，AGENTS.md 的 Skill 索引表、激活顺序（§19.3）、违规阻断列表（§19.4）都需要同步更新。

方案"本次允许事项"第 8 条说"允许新增 Trae Skill"，但未提及 AGENTS.md 同步更新。

**修改建议**：
在方案中明确追加一项允许/要求：
- "允许并要求同步更新 AGENTS.md §19 Skill 索引表，新增 `cairobot-llm-wiki-distillation` 条目"

同时建议明确该 Skill 的 priority 和 blocking 属性值。

## 四、建议修改项

### 4.1 🟡 建议与现有 tabbit-task-distillation Skill 明确关系

当前已有 [`tabbit-task-distillation`](../../.trae/skills/tabbit-task-distillation/SKILL.md) Skill 负责 Tabbit 任务的蒸馏。新方案要新增 `cairobot-llm-wiki-distillation` Skill 负责"三层蒸馏"。两者的关系需要明确：

- 是替代关系？还是互补关系？
- `tabbit-task-distillation` 的输出目标 `docs/reports/distilled/{YYYY}/{MM}/` 与新方案的 Distillation 层 `docs/wiki/daily/` 等目录是否重叠？
- 新 Skill 是否应调用/依赖旧 Skill？

**建议**：在方案中增加一节说明新旧 Skill 的职责边界和协作关系。

### 4.2 🟡 建议补充 docs/wiki/daily/ 目录的设计

方案提出新增 `docs/wiki/daily/` 作为 Distillation 层目录，但：
- 该目录与已有的 `docs/reports/daily/`（日报原始层）名称相似，容易混淆。
- 该目录与已有的 `docs/reports/distilled/`（蒸馏产物）功能边界不清。
- 没有给出该目录下的文件命名规范和内容模板。

**建议**：
- 要么重命名为 `docs/wiki/distilled-daily/` 以减少混淆，
- 要么在方案中明确三者的区别表格：

| 目录 | 层级 | 内容 | 生命周期 |
|---|---|---|---|
| `docs/reports/daily/` | Raw | 每日原始日报 | 不变 |
| `docs/reports/distilled/` | Raw→Distillation 过渡 | 每日蒸馏 Markdown | 由 tabbit-task-distillation 产出 |
| `docs/wiki/daily/` | Distillation | 经主控确认的稳定日知识 | 由三层蒸馏 Skill 产出 |

### 4.3 🟡 建议 Command 输出格式对齐现有模式

方案要求新增 `.trae/commands/llm-wiki-distill.md`，现有唯一 Command `/tabbit-task` 使用纯 Markdown 指令格式（无 YAML frontmatter）。新 Command 应保持一致格式。

另外，方案要求 Command 支持 5 种场景（每日蒸馏、任务蒸馏、SOLO Web 产物归档等），但每种场景的输入参数差异较大，建议在方案中给出各场景的调用示例。

### 4.4 🟡 建议明确"旧内容迁移"策略

LLM-WIKI.md 中已有大量内容（§5 已完成事项 30+ 条、§15 Tabbit 任务索引表含 7 个条目 + manifest 队列）。方案说要改为 Index 层入口，但这些旧内容的处理策略不明确：

- 已完成事项 30+ 条 checkbox → 移到哪里？还是直接删减？
- Tabbit 任务索引表（§15）→ 与新的"任务索引.md"如何合并？
- Manifest 蒸馏队列（§15 内）→ 是否也迁移到新索引？

**建议**：在方案中增加"旧内容迁移策略"章节。
