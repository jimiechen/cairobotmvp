# 协议编号注册表

## 1. 文件定位

本文件用于登记 CaiRobot MVP 项目中所有 Protobuf 接口报文的 `max + min` 编号。

所有 Request、Response、Event、Command、Callback 报文都必须在本文件登记。

任何新增、修改或删除协议编号的行为，都必须经过 PR 评审。

## 2. 核心规则

1. `max + min` 组合在全仓库内必须唯一。
2. 不允许两个不同报文使用相同的 `max + min`。
3. 已发布的 `max + min` 不得复用。
4. 删除接口后，原编号必须标记为 `reserved`，不得分配给新接口。
5. Request 和 Response 应分别拥有独立编号。
6. Event、Command、Callback 也必须拥有独立编号。
7. OpenAPI 接口必须映射到对应的 Protobuf Request 和 Response 编号。
8. PR 中新增协议时，必须同步更新本注册表。

## 3. 编号字段说明

| 字段 | 说明 |
|---|---|
| max | 协议大类，对应 `maxType` 或 `Type.max` |
| min | 协议小类，对应 `minType` 或 `Type.min` |
| 方向 | C->S、S->C、Service->Service、Webhook |
| 报文类型 | Request、Response、Event、Command、Callback |
| Proto 文件 | 报文所在 `.proto` 文件 |
| Message | Protobuf message 名称 |
| OpenAPI | 对应 OpenAPI 路径，如果没有则写无 |
| 状态 | 草案、已启用、已废弃、已保留 |
| 说明 | 接口用途 |

### 7.4 语言来源优先级规范

```
优先级 1（最高）: MessagePacket.extend.langCode
优先级 2（兜底） : 协议体 lang_code 字段（HelloReq/HealthReq.field 2）
优先级 3（降级）: configsdk 读取 system_cfg.default_lang_code
优先级 4（最终降级）: 硬编码默认值 "zh-CN"
```
