# 测试用例规范

## 1. 测试用例结构

每个测试用例必须包含以下字段：

### 1.1 基本信息

| 字段 | 说明 | 示例 |
|---|---|---|
| 用例 ID | 唯一标识符 | TC-001 |
| 用例名称 | 清晰表达测试目标 | 设备绑定成功 |
| 优先级 | P0/P1/P2/P3 | P0 |
| 创建日期 | 用例创建日期 | 2026-05-17 |
| 最后更新 | 用例最后更新日期 | 2026-05-17 |
| 创建人 | 创建者 | Trae |
| 相关 PRD | 关联的 PRD | PRD-00 |
| 相关 Issue | 关联的 Issue | #1 |

### 1.2 测试步骤

| 字段 | 说明 |
|---|---|
| 前置条件 | 测试执行前必须满足的条件 |
| 测试步骤 | 操作步骤，步骤编号从 1 开始 |
| 操作 | 每个步骤具体做什么 |
| 输入 | 每个步骤输入的数据或参数 |
| 期望结果 | 每个步骤期望的结果 |
| 实际结果 | 测试执行后的实际结果 |
| 证据 | 截图/视频路径 |

### 1.3 断言

- 每个测试用例必须有明确的断言
- 断言必须能清楚判断用例通过或失败
- 不能依赖人工主观判断
- 断言必须记录在测试报告中

## 2. 测试用例分类

按测试类型分类：

| 类型 | 说明 | 示例 |
|---|---|---|
| 单元测试 | 测试单个函数/类 | 意图分类函数 |
| 状态机测试 | 测试状态迁移 | 设备状态机 |
| 协议测试 | 测试协议解析/生成 | 通信协议 |
| 集成测试 | 测试模块间协作 | App + 固件 |
| 端到端测试 | 测试完整用户流程 | 从打开 App 到学习结束 |
| 安全测试 | 测试安全边界 | AI 过滤 |

## 3. 测试用例优先级

- **P0**：阻断核心流程，必须有
- **P1**：核心功能，必须有
- **P2**：重要功能，优先有
- **P3**：次要功能，可以有

## 4. 测试用例命名

测试用例命名应清晰表达业务含义：

推荐格式：

```text
TC-XXX_[场景名]_[期望结果]
```

示例：

```text
TC-001_设备绑定成功
TC-002_设备绑定失败_蓝牙未开启
TC-003_AI过滤_违规词被拦截
```

## 5. 测试用例存放

- 通用测试用例：`docs/testing/test-cases/`
- 模块特定测试用例：随模块目录存放
- 安全边界用例：`tests/safety-cases/`

## 6. 测试用例更新规则

- 需求变更时必须同步更新测试用例
- 修复 Bug 后必须新增或更新测试用例
- 重构后必须确认测试用例仍然有效
