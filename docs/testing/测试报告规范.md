# 测试报告规范

## 1. 测试报告要求

每次运行测试后必须生成测试报告。测试报告必须真实、具体、可追溯、可验证。

## 2. 测试报告结构

### 2.1 基本信息

| 字段 | 说明 | 示例 |
|---|---|---|
| 测试报告 ID | 唯一标识符 | REPORT-001 |
| 测试日期 | 测试执行日期 | 2026-05-17 |
| 测试人 | 执行测试的人或 AI | Trae |
| 当前分支 | 测试时的分支 | feature/init-spec |
| 相关 Issue | 关联的 Issue | #1 |
| 相关 PRD | 关联的 PRD | PRD-00 |
| 相关 ADR | 关联的 ADR | ADR-0001 |
| 相关测试用例 | 关联的测试用例 | TC-001, TC-002 |

### 2.2 测试环境

| 字段 | 说明 |
|---|---|

| 测试设备 | 硬件设备或模拟器 |
| 浏览器 | Web 测试用 |
| 硬件版本 | 硬件相关 |

## 3. 测试报告存放

测试报告存放于：

```text
docs/reports/testing/
```

文件命名建议：

```text
REPORT-XXX_YYYY-MM-DD_用例ID或功能名.md
```

示例：

```text
REPORT-001_2026-05-17_TC-001-TC-005.md
REPORT-002_2026-05-17_AI意图分类.md
```
