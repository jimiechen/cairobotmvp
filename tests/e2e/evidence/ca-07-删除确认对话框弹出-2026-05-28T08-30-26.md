# 删除确认对话框弹出 - 测试截图说明

## 测试用例编号
CA-07（删除流程 - 二次确认）

## 截图时间
2026-05-28 08:30:26

## 页面描述
在 Schema 列表中点击某条记录的 **"删除"链接** 后，系统弹出的 **删除确认对话框**，用于防止用户误操作导致数据丢失。

## 关键元素

### 1. 对话框基本信息
- **弹窗标题**：**"警告"**
- **弹窗类型**：模态确认对话框（Modal Dialog）
- **关闭按钮**：右上角 X 图标，可关闭对话框
- **背景遮罩**：半透明黑色遮罩层，阻止用户与背景页面交互
- **弹窗尺寸**：中等尺寸，居中显示

### 2. 警告图标与提示文字
- **警告图标**：左侧显示 **黄色/橙色** 的 ⚠️（感叹号三角形）警告图标
- **主提示文字**：
  > **"确认删除该 Schema？删除后不可恢复。"**

#### 提示文字解析：
| 文本片段 | 含义 |
|---------|------|
| 确认删除该 Schema？ | 明确询问用户是否要执行删除操作 |
| 删除后不可恢复。 | **关键警示信息**，告知用户此操作的严重性和不可逆性 |

### 3. 操作按钮区域
对话框底部包含两个操作按钮：

| 按钮 | 样式 | 功能 | 行为 |
|------|------|------|------|
| **取消** | 白色边框按钮（次要按钮） | 取消删除操作，关闭对话框 | 不执行任何删除操作，返回列表页面 |
| **确定** | **蓝色实心按钮**（主要按钮） | 确认删除操作 | 发送 DELETE 请求至后端，执行实际删除 |

> **设计要点**："确定"按钮使用醒目的蓝色主按钮样式，但未使用红色（避免过于刺激），同时通过文字提示传达操作的严肃性。

### 4. 背景页面状态
- **Schema 列表**：可见但处于禁用状态（遮罩覆盖）
- **列表数据**：显示完整的 5 条 Schema 记录
- **目标记录**：用户点击删除的那条记录在列表中可见（可能是任意一条）

## 预期行为

1. **二次确认机制的必要性**：
   - ✅ 删除操作属于 **破坏性操作**，一旦执行将永久移除数据
   - ✅ 二次确认可有效防止用户的 **误点击** 或 **手滑操作**
   - ✅ 符合 UX 设计最佳实践和用户心理预期

2. **对话框触发流程**：
   - 用户在 Schema 列表中找到目标记录
   - 用户点击该行右侧的 **"删除"链接**（红色文字）
   - 系统立即弹出删除确认对话框，阻止后续操作直至用户做出选择
   - 对话框弹出时，背景页面完全禁用，确保用户注意力集中在确认决策上

3. **用户操作选项及后果**：

   #### 选项 A：点击"取消"
   - 对话框关闭
   - **不执行任何删除操作**
   - 返回列表页面，所有数据保持不变
   - 可重新考虑是否需要删除

   #### 选项 B：点击"确定"
   - 对话框关闭
   - 前端发送 DELETE 请求至后端 API
   - 后端执行数据库删除操作
   - 删除成功后，前端刷新列表并显示成功提示
   - 删除失败后，前端显示错误提示（参见 CA-06 用例）

   #### 选项 C：点击 X 或按 ESC 键
   - 对话框关闭
   - 行为等同于"取消"

4. **无障碍访问（Accessibility）要求**：
   - 对话框应支持键盘导航（Tab 键切换焦点）
   - Enter 键应触发默认按钮（通常是"确定"，但此处建议"取消"更安全）
   - ESC 键应关闭对话框并取消操作
   - 警告图标应有适当的 alt 文本或 ARIA 标签
   - 对话框内容应对屏幕阅读器友好

5. **安全性考虑**：
   - 删除确认仅在前端进行，后端仍需进行权限校验
   - 应记录删除前的确认操作到审计日志
   - 对于重要或敏感的 Schema 记录，可能需要更强的保护机制（如需要输入确认文字、二次密码验证等）

## 测试结论
✅ **通过** - 删除确认对话框正确弹出，警告信息清晰明确，操作按钮功能符合预期。
