**数据特征分析**：

- 操作人均为 `admin`
- 时间间隔约 1 小时（10:00 → 11:00）
- 版本 2 即为本次刚发布成功的版本（与顶部"配置发布成功"提示对应）

## 预期行为

1. **条件加载**：仅在模块 Key 和环境均有效选择后才发起历史数据请求
2. **表格渲染**：
   - 表头固定显示 4 列：版本号、环境、发布时间、操作人
   - 环境列使用彩色标签（dev = 蓝色，prod 可能 = 红色/橙色）
   - 版本号按升序排列（旧版本在上，新版本在下）
3. **数据准确性**：
   - 仅展示当前模块 Key + 环境组合下的历史记录
   - 不混入其他模块或其他环境的数据
4. **发布联动**：每次成功发布后，表格自动追加新记录（无需手动刷新）
5. **空状态处理**：若该模块尚无发布历史，表格应显示空状态提示（如"暂无发布记录"）
6. **分页扩展**：当历史记录较多时，表格应支持分页（本截图中仅 2 条，无需分页）

## 表格设计规范

| 设计项 | 规范 |
|---|---|
| 表头对齐 | 左对齐 |
| 单元格内边距 | 适中（12px-16px） |
| 斑马纹 | 建议启用，提升长表可读性 |
| 环境标签 | 小圆角胶囊状，颜色区分环境类型 |
| 时间格式 | `YYYY-MM-DD HH:mm:ss` |

## 数据流向

```
用户选择 app.server + dev
        ↓
前端 GET /api/config/history?moduleKey=app.server&env=dev
        ↓
后端查询 config_version 表
        ↓
返回 [{version: 1, env: "dev", publishedAt: "...", operator: "admin"}, ...]
        ↓
前端渲染发布历史表格
```
