## 页面描述
在执行 Schema 删除操作时，由于 **传入无效的记录 ID**（如 ID 不存在、ID 格式错误或 ID 已被删除），系统返回 **删除失败** 的错误提示状态。

## 关键元素

### 1. 错误提示信息
- **提示位置**：页面顶部，面包屑导航下方
- **提示样式**：**红色背景**的错误提示条
- **提示图标**：左侧显示红色 ✕（叉号）或警告图标
- **提示文字**：**"删除失败"**
- **提示行为**：自动显示，通常会在 3-5 秒后自动消失（或支持手动关闭）

### 2. 错误触发场景说明
本测试用例模拟以下异常情况之一：

| 场景 | 描述 | 预期 HTTP 状态码 |
|------|------|:---------------:|
| **ID 不存在** | 尝试删除一个数据库中不存在的 Schema 记录 ID | 404 Not Found |
| **ID 格式非法** | 传入的 ID 不是有效的数字格式（如负数、非数字字符串） | 400 Bad Request |
| **ID 已被删除** | 该记录已被其他用户/进程删除，产生竞态条件 | 404 Not Found |
| **权限不足** | 当前用户无权删除该记录 | 403 Forbidden |

### 3. 页面状态
- **列表数据**：Schema 列表保持原有数据不变，未发生任何变化
- **弹窗状态**：无弹窗显示（删除操作通常为直接操作，无需二次确认或已确认后报错）
- **页面交互**：所有功能区域正常可用

## 预期行为

1. **异常处理完整流程**：
   - ✅ 用户点击某条记录的"删除"链接（或在确认对话框中点击"确定"）
   - ✅ 前端发送 DELETE 请求至后端删除接口，携带目标记录的 ID 参数
   - ✅ 后端接收请求，校验 ID 合法性及记录是否存在
   - ✅ 后端发现 ID 无效（不存在/格式错误等），返回错误响应
   - ✅ 前端接收错误响应，不关闭任何弹窗（如有），不刷新列表
   - ✅ 前端在页面顶部显示红色错误提示信息

2. **错误处理机制要求**：
   - 前端应正确解析后端返回的错误响应，提取错误信息
   - 错误提示应对用户友好，避免暴露技术细节（如 SQL 错误、堆栈信息）
   - 错误提示应有合理的持续时间，便于用户查看
   - 系统不应因单个操作的失败而影响其他功能的正常使用

3. **安全性考虑**：
   - 删除接口应进行严格的身份认证和权限校验
   - 应防止 ID 注入攻击（如通过修改 ID 删除其他用户的记录）
   - 应记录删除操作的审计日志，包括操作人、时间、目标 ID、结果等
   - 对于已关联配置数据的 Schema，可能需要额外的引用检查

4. **数据一致性保障**：
   - 删除失败不应导致任何数据变更
   - 列表数据应保持与操作前完全一致
   - 不应出现部分更新或脏数据的情况

## 测试结论
✅ **通过** - 系统正确处理了无效 ID 的删除请求，返回明确的错误提示，未影响现有数据。
