# CA-10 空 Fields 发布错误提示

## 测试用例信息

| 项目 | 内容 |
|---|---|
| 测试用例编号 | CA-10 |
| 截图时间 | 2026-05-28 08:31:00 |
| 页面路径 | 配置管理 → 配置发布 |
| 测试场景 | 未选择模块 Key 直接尝试发布配置时，页面不渲染动态字段且应阻止提交或给出错误提示 |

## 页面描述

截图展示的是 **配置值发布页面** 在模块 Key 未选择时的初始状态。模块 Key 下拉框显示占位符文本"请选择或输入模块 Key"，由于未选定模块，下方的动态配置字段区域未渲染（不存在任何字段输入控件）。这是配置发布流程的第一步校验守卫——必须先选择模块才能进入后续操作。

## 关键元素

### 1. 面包屑导航
- 路径：`首页 > 配置发布`
- 当前标签页：**配置发布**

### 2. 操作流程提示
- 文案：`操作流程：选择模块 → 填写字段值 → 点击发布 → 生成到对应环境`
- 强调第一步即为"选择模块"

### 3. 基础选择表单

| 字段 | 当前值/状态 | 必填标记 | 控件类型 |
|---|---|---|---|
| 模块 Key | `请选择或输入模块 Key`（占位符文本） | *（必填） | 下拉选择/可输入 |
| 环境 | `开发 (dev)`（已预选） | *（必填） | 下拉选择框 |

**关键观察**：模块 Key 处于**未选中状态**，显示 placeholder 文本而非实际值

### 4. 动态配置字段区域
- **状态**：**未渲染 / 不存在**
- **原因**：由于模块 Key 未选择，系统无法获取对应 Schema，因此无法生成动态字段
- **表现**：表单区域仅有基础选择区和操作按钮，中间无任何字段输入控件

### 5. 操作按钮
- **↑ 发布配置**：蓝色按钮，但在模块 Key 缺失时应为禁用状态或点击后触发前端校验提示
- **重置**：灰色按钮

### 6. 前往 Schema 链接
- 位置：右上角
- 文案：`← 前往 Schema`

## 预期行为

1. **前置依赖校验**：模块 Key 是整个配置发布流程的前置必选项，未选择时不渲染下游字段
2. **联動逻辑**：
   - 用户选择模块 Key → 前端请求该模块 Schema → 动态渲染字段表单
   - 用户清空模块 Key → 清空已渲染的动态字段
   - 用户未选择模块 Key → 不显示动态字段区域
3. **发布拦截**：
   - 方案 A（推荐）：模块 Key 为空时，"发布配置"按钮置灰 disabled，不可点击
   - 方案 B：允许点击但前端即时校验，弹出 toast 提示"请先选择模块 Key"
4. **占位符引导**：下拉框的 placeholder 文本清晰告知用户需要执行的操作
5. **环境独立**：环境的预选/选择不依赖于模块 Key，两者为并列必填项

## 错误预防机制

本截图体现的是**前端防御性校验**的设计思路：

| 校验层级 | 校验时机 | 校验内容 | 错误展示方式 |
|---|---|---|---|
| L1 前端即时 | 选择变化时 | 模块 Key 是否有效选项 | 下拉框自身状态 |
| L2 前端提交前 | 点击发布按钮时 | 模块 Key 是否为空 | 按钮 disabled 或 toast |
| L3 后端校验 | 请求到达服务端 | 模块 Key 是否存在且有对应 Schema | 返回错误码 + 提示 |

## 与其他状态的对比

| 场景 | 模块 Key | 动态字段 | 可否发布 |
|---|---|---|---|
| 本截图（CA-10） | 空（placeholder） | 不渲染 | 否 |
| CA-08 动态表单 | app.server | 渲染 3 个字段 | 是（填写完整后） |
